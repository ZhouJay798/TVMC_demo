# 2026-11-14 成员核验后解密得分

改动对应新版论文算法 6 的成员重算要求。代码说明见 [成员批准流程](../../docs/MEMBER_SCORE_APPROVAL.md)。

验证命令：`.venv/bin/python -m pytest -q`。最终输出见 [tests.txt](tests.txt)。

| 场景 | 验证内容 |
|---|---|
| 正常文件证据 | 码本登记、发行绑定、成员重算、三份结果合并、阈值归因及公开验证 |
| 正常得分批次 | 两个副本分别得到 +4 和 -4；没有解密完整码本 |
| 指纹位密文冒充得分 | 在 te.partial 调用前拒绝 |
| 改动得分、遗漏副本 | 整批比对拒绝，不能只提交有利的副本 |
| 替换可疑码字、密钥、检查点、证据、日志 | 在使用份额前拒绝 |
| 重放请求 | 同一成员批准对象拒绝再次使用已消费的组 |
| 合成 API 证据链 | 三位签名采集者→成员重新核验→重算得分→归因→公开 Judge 通过 |
| 篡改 API 原始响应 | 即使重建日志哈希链，成员仍在部分解密前拒绝无效采集签名 |
| 篡改成员批准 | 即使重建日志哈希链，公开 Judge 仍拒绝无效批准签名 |
| 既有回归 | HPKE、双 DKG、交付、日志、TLS pin、转发申辩及模型读出相关测试 |

这些是协议回归与合成 API 实验，未在本次重新训练真实大模型、跑量化剪枝实验或完成真实模型 API 全链路验收。旧真实模型结果继续以 reproduction_20261113 为准。

仍然是同进程角色模拟。没有 CA、独立成员主机、持久化审批状态或对达到门限合谋的密码学防护；不能声称部署隔离已经完成。
