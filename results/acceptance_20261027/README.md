## 改进实验与原流程的区别

- `run_demo.py`：原密码学托管—恢复—模型指纹—Judge 链路。
- `run_robustness.py`：重新训练自然触发、三重冗余、效用约束，并比较分组量化、二阶剪枝与输入过滤。
- `run_distillation_research.py`：普通输出统计指纹，固定已验证候选后重新训练学生及原方案对照。候选选择阶段未重复搜索，以避免根据最终测试调参。

研究改进不是已经全部接入原注册表与 Judge 的一条统一发布流程。尤其新统计指纹不直接恢复旧 256 位 Tardos 码字，需要完整词表概率及干净基座对照，不能自动继承原抗合谋/公开裁决性质。

## 实际边界

1. 严格单输入盒的证据量不足，不能用一次批量请求偷换概念。
2. 二阶剪枝虽减轻损伤，仍有明显输出变化。10% PPL / 90% 一致率是 Demo 工程门槛，不是论文规定。
3. 原触发指纹的过滤/蒸馏失败仍存在；改进在特定测试中有效，不覆盖任意攻击。
4. 生成文本蒸馏仍可在保持较低 PPL 损失时移除统计指纹。
5. 模型是 SmolLM2-135M；没有验证任意规模模型、所有任务能力或跨架构完整学生训练。

## 复现（Windows PowerShell）

先按项目 README 安装 Python 3.12 和研究依赖。模型与 WikiText 均已缓存后运行：

```powershell
.\.venv\Scripts\python.exe -m pytest -q
.\.venv\Scripts\python.exe run_demo.py --device cpu --offline
.\.venv\Scripts\python.exe run_robustness.py --device cpu --offline
.\.venv\Scripts\python.exe run_distillation_research.py --offline
```

如模型在独立目录，可为对应命令追加 `--model-path .\models\SmolLM2-135M`。研究码本不能当作原注册表签发的身份凭据，不要把研究输出目录传给原证据验证接口。

本次真实输出分别归档在 core、robustness、distillation 子目录。测试和独立证据验证见 validation.txt。没有修改模型算法或降低门槛来改变本次验收结论。
