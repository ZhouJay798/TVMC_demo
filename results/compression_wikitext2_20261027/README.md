# WikiText-2 压缩配对复测（2026-10-27）

使用同一 SmolLM2-135M 基础模型与现有用户 1 检查点，重新执行量化、剪枝和 PPL 评估，没有重新训练指纹。旧版检查点来自本次原始端到端验收，新版是自然语言冗余指纹，不是全词表统计指纹。无法读取用户 Windows 本地权重，故本表是云端配对复测，不能称为用户本机实测。

WikiText-2 raw 固定修订，去重、过滤后的 test[128:192] 共 64 段，每段至多 96 tokens，共 6,073 个预测词元。这不是完整 WikiText-2 标准基准；不可与旧 124-token 小语料直接比较。

表内括号均为相对未嵌入指纹、未压缩原模型 PPL 的增幅。

| 操作 | 无指纹 | 旧版特殊触发指纹 | 新版自然语言冗余指纹 |
|---|---:|---:|---:|
| uncompressed | 38.858（+0.00%） | 45.429（+16.91%） | 39.458（+1.54%） |
| row_int8 | 39.886（+2.64%） | 46.500（+19.67%） | 40.485（+4.19%） |
| magnitude30 | 73.885（+90.14%） | 90.477（+132.84%） | 77.456（+99.33%） |

共同分母：干净原模型 PPL = 38.858045。增幅 = (对应模型压缩后 PPL / 干净原模型 PPL - 1) × 100%。分母相同，但压缩对象不同，分子不同，因此增幅不同。

只衡量压缩带来的额外变化，应除以各自未压缩模型的 PPL；该指标保存在 metrics.json 的 increase_vs_own_uncompressed，不能与共同分母指标混用。

INT8 是逐行舍入后浮点计算；剪枝是当前朴素约 30% 幅度剪枝，不是二阶补偿方法。操作范围是 backbone Linear 权重，排除 embedding/head。

run.log 为原始输出，其中 next_token_agreement=1.0 是未传入参考预测时辅助函数的默认值，不能作为一致率实验结果；已从 metrics.json 排除，复现脚本也不再输出该字段。
