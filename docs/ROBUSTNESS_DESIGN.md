# 鲁棒性改进：依据、实验协议与边界

本轮以用户提供的 TVMC 原文为依据，同时核对 SparseGPT 官方算法源码。
原文 §7 的数值是占位值；§5 备注 19 明确承认过滤/蒸馏可能破坏鲁棒嵌入假设。
这里不把论文中的条件性保证写成已实现的安全性。

## 方法与来源

| 改动 | 来源 | 实现范围 |
|---|---|---|
| 码位冗余、软读出 | TVMC §6.3、附录 A.7 | 每位 3 个自然文本前缀；聚合实际 0/1 logit 差，再用原 Tardos 阈值解码 |
| 效用约束 | TVMC §4.4 | 普通校准文本上的完整词表 KL + 输出漂移 + 权重范数约束 |
| 分组 INT8 | 常规分组权重量化 | 每行 32 个元素一组，仍为 8 位量化，反量化后浮点推理，不宣称加速或压缩存储 |
| 二阶剪枝补偿 | SparseGPT，ICML 2023 | 在公开普通文本上估计 Gram/Hessian，剪枝时补偿重构误差；无秘密触发器校准 |
| 自然触发器 | 针对 TVMC 分布外触发可被过滤的工程探索 | 真正自然文本前缀，无固定标记；不是原文已经证明的抗过滤构造 |
| 两种蒸馏评估 | TVMC §7.5 的评估要求 | 完整概率 KL 与硬标签分别训练干净基座的新 LoRA 头，保留失败结果 |

SparseGPT 论文：https://arxiv.org/abs/2301.00774

官方实现：https://github.com/IST-DASLab/sparsegpt

改写部分的 Apache-2.0 许可及署名在 `third_party/`。本实现不是上游完整的逐层顺序校准流水线，不冒充其论文性能。

## 预先固定的对照

- 同一 SmolLM2-135M、同一码本、5 用户、256 位、固定指控阈值；不降低误告要求。
- 旧版随机词元触发器作为 `original`，新版为 `natural_redundant`。
- 原版查询 256 个输入，新版查询 768 个输入，查询成本显式增加。冗余不是免费提升，也不解决严格单输入盒。
- 自然触发的三个前缀来自同一段落，错误可能相关，因此不套用独立错误的二项分布公式。
- INT8 比较逐行量化与 group-size=32 分组量化。
- 剪枝比较原始幅度剪枝、二阶补偿剪枝，以及保留注意力、剪 MLP 的分配策略。
  对 SmolLM2，MLP 占主干 Linear 参数的 75%，MLP 剪 40% 对应整体约 30%。
  所有方案记录真实零权重数和分母；不隐瞒原始 bfloat16 权重并列值造成的细微比例差异。
- 每种压缩都报告干净模型对照和水印模型结果；每轮恢复原权重后独立执行。
- 保留原 12 句语料指标，但新增 WikiText-2 数千 token 的主要效用指标。
- 标准继续为 PPL 相对增加 ≤10%、next-token 一致率 ≥90%。改善未达标时不能标为全部通过。

## 数据分离

数据：`Salesforce/wikitext` 的 `wikitext-2-raw-v1`，固定 commit
`b08601e04326c79dfdd32d625aee71d232d685c3`。

去掉短文本/标题和精确重复后，使用：

- train 中排除前 384 个段落后，固定随机种子 2026 跨文档抽取 128 段：校准/效用正则；
- train 的 64..127：学生蒸馏；
- train 的 128..383：256 位指纹的自然触发；
- validation 的 0..63：开发诊断；
- test 的 0..63：早期开发实验，不能称最终盲测；
- test 的 64..127：第二个候选版本失败的开发评估；
- test 的 128..191：最终固定评估，默认 `--test-offset 128`。

记录所有文档 SHA-256，验证精确文本不重叠。不同文档可能来自同一文章，不能把这当作主题独立或完整 benchmark。
训练/校准过程不使用最终评估文本。源码不重新分发数据正文，运行时下载官方数据文件。

## 过滤和蒸馏不是“换弱攻击”

过滤包括原来的固定前缀规则、按校准文本 NLL 第 95 百分位设置的异常输入过滤，以及统一小写/空格归一化。
记录触发拒绝率、正常请求拒绝率、码位覆盖率和指控对象；完全没有观测的码位是擦除，不强制猜测。
输入改写可能改变任务，不能把未测的改写后效用宣称为不变。自然前缀通过这些过滤，也不等于抵御任意自适应过滤。

学生不接收秘密触发列表、码字或正确码位标签。软蒸馏目标是实际教师的完整词表概率。
因为两者固定相同主干、只有 0/1 输出行可变，其 KL 可以按两个词元和其余词元概率质量精确计算；这不是截断 top-k。
硬蒸馏使用实际教师 argmax，另行测试。主实验 500 步预算对原版和新版相同；附加攻击保持 12 步软蒸馏，并测试带干净模型 KL 效用约束的 500 步硬蒸馏，防止只选择有利的训练预算。
两种实验都只是干净同架构基座上的头部蒸馏，不代表从零训练整模型或所有架构的蒸馏攻击。

软读出依赖接口提供候选词元 0/1 的概率或 logits；不能把它等同于只返回自由生成文本的接口。当前自然触发仍使用这两个输出行的 LoRA，没有实现注意力层嵌入或学生模拟训练。此类方向需要新的实现和独立实验，不能引用本轮结果当成已验证。

保持普通输出不变的稀疏信号，可能根本不会进入硬标签训练数据。不能通过给学生秘密触发样本来伪造抗蒸馏成功。

## 发布门槛和结果解释

单元/接口测试必须通过；配对对照必须显示实际改善。`improvement_gates` 表示若干明确改进门槛，
不是“所有研究目标成立”。`all_attacks_solved` 单独记录，任何失败都保留。

原 `run_demo.py` 保留作为端到端密码学基线；`run_robustness.py` 是新增模型层对照入口，
其固定研究码本不是原注册表签发的身份记录，不能将其结果当作公开 Judge 的新归因证据。
密码学绑定的集成必须单独验证，不能仅因模型层改善而自动声称系统安全性提升。

## 干净学生对照与无法保证的目标

SmolLM2 是公开模型，干净学生在看教师之前已经拥有基准语言能力。因此额外记录零教师训练的学生能否维持效用、以及是否会被错误指控。不能据此设定“所有保持基础语言能力的学生都必须带有被盗指纹”的无条件目标。要研究保护真正有增量价值的私有模型，应另行定义私有任务收益和学生提取效果；本轮没有伪造这样的任务。

完整结果之外，保留两轮未达标候选及其停止/完成状态。第一轮测试只用作开发诊断；第二轮因新测试语料 PPL 超过 10% 被停止，未执行阶段明确标记。最终方法不再根据最终测试结果调参，若仍失败照实报告。

## 剪枝后的固定掩码恢复

`run_pruning_recovery.py` 对幅度剪枝和二阶补偿剪枝使用相同 50 步 Adam、学习率 3e-5、普通校准文本上的完整词表干净教师 KL。只更新主干 Linear 的非零权重；每步重施掩码，冻结嵌入、归一化和指纹头，不提供秘密触发器。验证日志也保留了 30 步普通语言建模 CE 恢复的尝试，不能混为最终配对设置。

恢复可能改善困惑度却不能恢复下一词元一致率，所以仍同时报告两项效用门槛及恢复后定位。主实验、附加蒸馏反例、恢复对照和开发失败统一归档在 [实测结果](../results/robustness_20261025/README.md)。

实际恢复的是干净主干，随后重新装载同一份保存的指纹头，保证两种压缩使用相同恢复目标；没有联合恢复水印头与主干。二阶补偿 + 恢复后新版 PPL 增幅 11.17%、一致率 81.44%，仍未达标，不将该补测写成剪枝问题已解决。
