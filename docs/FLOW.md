# 当前项目运行流程

## 一、建立参与者与密钥

1. 创建五名托管方。每人拥有独立的身份签名密钥和 X25519 接收密钥。
2. 身份签名绑定成员编号及接收公钥；通过 HPKE 加密挑战检查接收私钥持有性。
3. 成员各自贡献多项式，先给出 Pedersen 承诺，再进行份额验证与 Feldman 提取，得到 3/5 联盟释放密钥。
4. 独立重复生成码本密钥。一个用于交付/探针托管，另一个用于解密追踪分数，不混用。

当前在一个 Python 进程内模拟角色，未连接真实机构身份系统；演示的是协议运算与验证，不是操作系统级隔离。

## 二、准备和验收指纹模型

1. 加载真实的本地 SmolLM2，业务更新只作用在最后五层 MLP 输出矩阵。
2. 从自然语料取探针，挑选业务更新影响较小的位置，并选取在所有者模型与基座上都接近平分的秘密 token 对。
3. 每位指纹对应三个探针，分散到不同矩阵；一次计算输入方向、双正交输出方向和共享载体。
4. 用三份独立均匀测试码字校准统一增益。必须同时满足读回错误不超过 2% 和校准集下一词预测一致率至少 85%，否则停止发行。
5. 截断扫描保留通过和失败结果；即便存在可去指纹攻击，仍可演示受控交付，但明确限制追踪范围。
6. 正式副本按 Tardos 偏置抽样码字，以相同载体的不同符号生成。没有逐人 LoRA 训练或推理时按副本编号查码字。

## 三、逐人封装、批准和接收

1. 首次释放前承诺读码参数并门限托管探针。为每个副本登记加密码本和每位为 0/1 的 OR 证明。
2. 每个副本独立随机生成 AES 数据密钥与隐藏随机量，分块加密完整模型 ZIP。
3. 接收人的 HPKE 公钥封装数据密钥及隐藏随机量；联盟 TDH2 混合胶囊保护这个内层包。
4. 发行者签署副本编号、接收人、公钥、隐藏副本承诺、密文哈希、胶囊哈希和码本哈希。
5. 接收人签署领取申请；三个不同成员先签署意向，再计算并签署部分解密和正确性证明。
6. 合并者验证三个结果，打开外层，得到仍然加密的内层包。只有接收人私钥能取出数据密钥。
7. 接收人分块解密并检查完整性、清单和副本承诺；成功后签收。

## 四、文件取证

1. 固定疑似文件哈希。
2. 三人批准披露筛查探针，实际加载模型运行筛查；不通过则不消耗归因探针。
3. 承诺归因调查，三人批准披露归因组；实际模型返回每个秘密 token 对的 logit 差，聚合成 0/1/擦除。
4. 在加密码本上计算 Tardos 分数，门限解密分数而不是整份码本。
5. 固定点舍入使用保守阈值修正，超阈值副本映射到发行清单里的接收人。
6. 公开复核重新加载疑似模型、重算读码和分数，验证发行签名、证明、公钥绑定、日志顺序及一次性探针使用。

## 五、API 取证与转发申辩

1. 固定端点、TLS 证书哈希及时间窗，然后披露探针。
2. 三名取证成员通过实际 HTTPS 连接分别查询，各自签署原始响应；读出的码字必须完全一致。
3. 相同的加密评分流程产生来源指认。端点描述的哈希用于固定调查对象，它不是模型权重哈希。
4. 转发模式启动两个 TLS 服务：疑似服务将请求转发到 U1 合法服务；合法服务记录输入摘要、MinHash、客户端及时间，锚定签名链头。
5. 申辩核验已锚定日志，删除可证实为转发的码位，重新进行同态评分和门限解密。
6. 重算不达阈值则撤销权重泄漏指认，保留“转发关系”。不能把来源命中直接理解为故意泄漏。

API 实验是本地服务演示，没有外部独立见证。`relay` 模式的日志锚定时间容差为 1800 秒，目的是容纳 CPU 实验；正式部署需根据可信时钟和风险要求单独设置。
