# 同一会话内的三份逐人指纹模型及双层封装

`run_personal_delivery.py` 使用五人预登记和至少两人会话准入机制，选择托管方1、2、3组成C-E0会话；每人持有一份会话密钥份额，门限3/3。每位参与方另有独立RSA-2048接收密钥，公钥指纹通过身份秘密知识证明绑定到会话、接收方、身份承诺和准入挑战，并提供RSA-PSS私钥持有证明。

三份模型分别对应C-E0-U1、U2、U3，指纹种子绑定会话、周期、副本编号、托管方编号、身份承诺及个人公钥指纹。码本固定为3候选、256位，阈值在训练前固定，三个适配器分别训练1200步。完整模型包含基座safetensors、分词器、配置和适配器。

## 密码学封装

1. 各副本独立随机生成32字节数据密钥D，AES-256-GCM加密完整模型包。
2. RSA-OAEP/SHA256以对应个人公钥封装D，OAEP label绑定规范化上下文哈希。
3. 会话密钥经已有HKDF/AES-GCM封装第二步的OAEP密文。
4. 接收方先通过全员份额及证明恢复会话密钥，再打开外层，用自己的RSA私钥打开内层，最后解密模型。

所有层绑定会话、周期、副本、接收方、身份承诺、公钥指纹和模型包哈希；密钥封装额外绑定模型密文哈希。每次AEAD使用随机nonce。该方案使用现有标准原语，不声称是某个HPKE标准套件或已经过生产安全审计的协议。

## 运行和输出

```bash
.venv/bin/python -m pytest -q
.venv/bin/python run_personal_delivery.py --output work/personal_delivery/new_run
```

新运行目录必须不存在。`crypto_metrics.json` 是五组独立随机性的小载荷封装检查，不能算模型训练重复。三个模型各训练一次，完整密文为 `*.aesgcm`，封装及绑定上下文为 `*_envelope.json`；指纹及效用见 `model_metrics.json` 和逐次HTTP记录。RSA私钥、会话秘密、DEK只在本次本地模拟进程内使用，不导出到公开记录；运行结束后需要重跑实验来产生新的可用密钥材料。

为控制磁盘使用，完整明文ZIP在内存构造，解密后在临时目录重新加载。中间适配器仍保留在本地实验工作目录，且基座模型可用；此工作目录本身不构成对恶意本地用户的访问控制边界。生产系统需要隔离托管方、保护私钥和明文，不能直接共享这个工作目录。

## 黑盒与一次性盒边界

真实推理服务仅向测量客户端返回0/1词元logit差；客户端用预登记候选码本进行解码。主测试的一次HTTP请求含768个自然文本前缀，每3个输入聚合一位，共256位。第二次请求应被拒绝。此结果依赖接口允许批量输入并如实返回分数，不能外推到纯文本聊天API。

严格单输入测试使用另一个独立一次性服务，一次只提交1个前缀并获得1个分数；实现拒绝补齐或猜测256位，返回证据不足。它与768输入批量协议是两个不同的接口条件。

转交对照：将U1的已解密模型放在标注为模拟U2操作者的服务下，重新读取指纹。该实验不重训、不改权重，用来区分登记副本来源与当前操作者。即使指纹正确定位U1副本，也不能据此认定U1实施泄漏。服务操作者标签是实验设定，并非远程身份认证。

信任边界：身份登记、模型生成组件及候选码本由本地可信程序提供；整个流程在同一进程模拟多方，不包含真实私密通道、远程证明、真实身份核验或可信外部日志。指纹不能阻止复制、转交、凭证被盗或恶意生成方嫁祸。一次成功授权也不会撤销已获得的会话密钥、DEK或明文。
