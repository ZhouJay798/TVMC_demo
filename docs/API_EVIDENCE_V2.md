# API 证据 v2：完成时间、失败消耗与一致读出

本次按新版论文的取证先承诺、多人独立采集、单次使用探针组和公开核验要求补强。

## 已复现的问题和修复

1. 旧采集器只记录发送请求前的 time。三位采集者分别于 102、103、104 时刻发起请求，最后一个响应在 106 完成，而时间窗口到 105 截止，旧实现仍接受。新实现对新证据签署 time、finished、evidence_version=2，并要求 start <= time <= finished <= end，超时结果不进入有效 endpoint_evidence。
2. 原采集失败时不留下占用记录，可能再次使用同一已经披露的组。现在发送任何探针之前写入 endpoint_collection_started，先核验参与者证书；失败也保持消耗状态。不能复用该组自动重试，需要新组/新实验。当前持久日志仍是单写者，不构成分布式并发事务保证。
3. 公开 API Judge 原来固定按 3 个探针重复读一位。现在读取已承诺参数中的 repeats；新增 repeats=2 的完整合成 API→成员批准→门限评分→公开 Judge 回归。
4. 拒绝非有限读数和有限值求和产生的溢出，并检查 repeats 与读出阈值是否合法。

## 版本与信任边界

- 新的 collect_quorum 总是生成 v2；finished 和版本号均在成员签名覆盖范围内，不能保留原签名再删字段或改时间。
- v2 记录缺少完成时间、完成早于开始、超过窗口、版本不支持，均拒绝；同一批采集证据不能混用 v1/v2。
- 历史 v1 证据保留只读兼容核验，只能确认原有发起时间，不可用新代码声称其完成时间也被验证过。
- 允许重复审计同一份合法历史证据；不允许对已经开始采集的组再次发起新的采集。
- 成员签名时间是采集者声明的本机时间，不是独立可信时间戳；仍依赖少于门限的恶意成员和诚实采集者的时钟/运行环境假设。
- 当前仍是本地角色模拟，不能防止控制整个进程或达到门限成员合谋。此修改不解决模型平均、基座复位和低秩截断的指纹鲁棒性问题。

## 验证范围

新增测试见 tests/test_api_evidence_security.py：替换端点、TLS 指纹、时间窗口、调查组、探针文本和 token；采集人数不足、重复成员、身份/签名/原始响应篡改；超时/倒序/缺失/NaN 时间；未知或混合证据版本；响应不完整、NaN/Infinity/求和溢出；读出参数非法；正常与历史证据兼容；失败后不可重试；未承诺端点不发送请求；非默认重复次数的公开核验。

真实模型转发链路和独立验证报告见 results/api_evidence_hardening_20261114。没有把一次合成时间对照称为真实网络延时攻击，也没有把修复后的流程通过称为所有泄漏手段均被抵御。
