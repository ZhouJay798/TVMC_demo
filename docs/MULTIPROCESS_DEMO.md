# 多进程模型分发与追踪演示

`run_multiprocess_demo.py` 在**同一台机器、同一操作系统用户**下启动不同的 Python 进程，模拟模型分发者、登记管理员与五位托管方。它演示各方如何交换公开材料、签名、份额和加密模型，**不是**独立机构之间的生产级托管系统。

## 参与进程及其职责

每次运行包含一个协调者和七个独立子进程；PID 写入 `metrics.json`：

| 进程 | 主要工作 | 私钥/秘密所在位置 |
| --- | --- | --- |
| 协调者（运行入口的主进程） | 验证五人预登记和 U1/U2/U3 的申请；生成本次 3/3 会话秘密和份额；收集份额并恢复外层包；本地检测各副本指纹 | 它知道初始会话秘密和全部生成的份额，恢复时也会收到三个份额值；因此它是受信的本地分发/恢复协调者。 |
| 分发者子进程 | 根据三组码字训练三份模型、保存合并模型包；为每份包生成独立 AES 数据密钥并加密，用对应人的 RSA 公钥封装密钥；对发行清单签名并加密整个外层包 | 分发者 Ed25519 私钥在该子进程生成；分发者知道模型明文、数据密钥和收到的会话秘密。 |
| 管理员子进程 | 重新验证公开准入信息及接收人公钥绑定，签署训练前预登记；发行后验证分发者签名和清单与预登记是否一致，再签署发行登记 | 管理员 Ed25519 私钥在该子进程生成。管理员预登记时尚无发行清单；分发者签名是在发行登记阶段验证的。 |
| U1、U2、U3 子进程 | 预登记、证明身份秘密及 RSA 私钥持有；保管各自的会话份额；在本进程验证签名登记、发行清单和自身绑定，再用自己的 RSA 私钥解密自己的模型包 | 每人自己的身份秘密和 RSA 私钥在对应子进程生成，不由角色 API 返回；份额值会提交给协调者恢复。 |
| U4、U5 子进程 | 生成自己的身份材料并完成预登记 | 本次未申请进入 U1/U2/U3 的会话，也不参与这次 3/3 恢复。 |

子进程通过继承的标准输入/输出交换 JSON 消息，较大的模型包及密文通过本机文件交换。RSA 和 Ed25519 私钥不通过该角色 API 导出；这不等于同一操作系统用户下的强安全隔离。

## 一次运行的过程

1. 启动分发者、管理员、U1–U5 七个子进程，检查它们与协调者的 PID 均不同。
2. 五位托管方各自产生身份预登记信息；U1、U2、U3 以身份知识证明申请会话，并以 RSA 签名证明个人公钥持有。
3. 管理员进程验证申请和接收人公钥绑定，生成并签署三人预登记快照，记录各副本、接收人、公钥、指纹码承诺及参数。
4. 协调者作为本地可信分发者生成 3/3 会话秘密和份额，分别发送给 U1、U2、U3。各托管进程检查份额与公开承诺及自身身份的对应关系。
5. 分发者子进程为每个接收人训练对应的 256 位指纹，将更新合并进模型权重，生成三份 ZIP 模型包。每包单独 AES-256-GCM 加密，数据密钥用对应接收人的 RSA-OAEP 公钥封装；分发者对发行清单做 Ed25519 签名，再用会话秘密派生的密钥加密外层包。
6. 管理员子进程独立重建并检查准入状态，验证分发者签名，核对发行清单和预登记，签署发行登记快照。
7. U1/U2/U3 各自生成请求绑定的份额知识证明并提交份额值。协调者检查参与集合、份额承诺和证明，恢复会话秘密；本演示调用分发者进程的签名密钥签署恢复回执。
8. 协调者用恢复的秘密打开外层包。各接收人进程分别验证分发者签名、管理员的预登记及发行登记签名，核对自身身份、公钥、上下文和密文哈希；验证通过后，使用本人的 RSA 私钥解封本人的数据密钥并解密模型包。
9. 协调者读取每人输出的模型 ZIP，加载完整模型并以已登记的 768 个探针做本地前向推理、汇总和 Tardos 解码。检测在协调者本进程执行，**此入口没有启动 HTTP 服务**，不应将其作为远程黑盒来源证明。

恢复过程在 `tvmc/process_recovery.py` 中接收 `i`、份额值和证明，不接收通常包含在 `Share` 中的身份秘密 `gamma`。协调者本身创建并知道本次份额，恢复时也会看到份额值；它不是分布式密钥生成或门限解密。

## 运行：离线集成演示

在项目根目录、依赖已经安装的情况下：

```bash
HF_HOME="$PWD/.cache/huggingface" .venv/bin/python run_multiprocess_demo.py \
  --offline-fixture --output work/multiprocess/fixture_run
```

`--output` 必须是**尚不存在的新目录**。默认每个副本训练 1200 步；`--steps` 可指定正整数，减少步数有助于快速检查进程通信，但可能不足以正确检出指纹，脚本会将相应检查标为失败。命令退出码 `0` 表示本次列出的检查均通过；退出码 `2` 表示流程跑完但至少一项检查未通过，异常中断也可能留下不完整输出。

`--offline-fixture` 使用随机初始化的小型 Transformer 和合成文本，确实执行模型权重训练、加密、解密与模型前向检测，但仅供集成测试，**不是预训练 SmolLM2 的效果，也不能证明真实模型鲁棒性**。本次检测使用训练所用的同一组 768 个探针，其中每三条来自同一文本窗口；不能作为未见过探针或 768 个独立样本的结果。

## 运行：已有本地真实模型

已按 [TRUSTED_WORKFLOW.md](TRUSTED_WORKFLOW.md) 准备好 PyPI 分发的 SmolLM2-135M-Instruct Q4_1 反量化模型和固定 Tiny Shakespeare 文本后，可运行：

```bash
HF_HOME="$PWD/.cache/huggingface" .venv/bin/python run_multiprocess_demo.py \
  --model-path models/SmolLM2-135M-Instruct-Q4_1-converted \
  --text-corpus .cache/public_data/tinyshakespeare-6f9487a.txt \
  --output work/multiprocess/public_model_run
```

也可以用 `--model-path` 指向其他已准备好的兼容本地模型目录。模型目录必须含 `model.safetensors`、配置和可用分词器；若省略 `--text-corpus`，程序需要对应的本地 WikiText-2 缓存，可用 `--cache` 指定缓存路径。使用原始 SmolLM2 与本例 Q4_1 反量化模型时，应分别记录来源和哈希，不能把它们当成相同权重。

真实模型的训练、压包、解密和逐份推理比离线夹具耗时得多。当前 `seal_bundle` / `open_bundle` 等路径会将多份模型包、ZIP 与密文读入内存，峰值远大于单个模型大小；一次性 AES-GCM 操作还可能受底层单次输入长度限制（约 2 GiB 量级）影响。不能据此推断能处理任意大模型；规模化需要重新设计分块认证加密、流式存储和相应的完整性校验。

## 输出和复核

输出在指定的新目录内，主要包括：

- `metrics.json`：进程 PID、模型范围、每份副本哈希和检测结果、正反向检查及局限。先检查 `status` 和每项 `checks`，再解释结果。
- `MULTIPROCESS_REPORT.md`：本轮角色分工、模型定位结果、检查项目及信任边界的中文摘要。
- `public_registration.json`：用于复核的预登记、准入证明、参与者公钥及公开承诺，不包含身份秘密、RSA 私钥或份额值；该材料仍可能涉及身份和业务元数据，需适当管理。
- `registry_precommit.json`、`registry_issued.json`、`signed_manifest.json`：本次本地登记签名和发行清单；公钥在本次运行内生成和传递，不是经过独立认证的现实机构信任根。
- `reconstruction_receipt.json`：由本次分发者密钥签发的恢复回执，不是独立恢复服务的证明；它不能证明未经过本服务的离线恢复一定留痕。
- `outer_bundle.aesgcm` 和 `encrypted_transit/`：外层密文及拆出的个人密文和密钥封装。
- `custodians/U1/received_model.zip` 等：托管方进程实际解出的**明文模型包**；`audit_codebook.json` 和 `audit_prompts.json` 保存本地演示码本、开启值和探针，也属于敏感数据。
- 离线夹具模式的 `fixture_source/` 是随机初始化的合成模型，不应误认为实际预训练模型。

运行时用于分发者中间明文的临时目录在正常结束时清理，突然终止时应检查是否残留。输出目录按用户专用权限创建，相关文件也按本地用户专用权限保存；同一 OS 用户或更高权限仍可能读取这些内容。**不要公开上传运行目录、明文模型、码本或探针。**

新版本运行结束后，可以使用 `audit_multiprocess_demo.py` 在另一个进程复核登记、签名、承诺、回执、外层密文字节及各托管方收到的 ZIP 字节。调用方需通过独立可信渠道取得发行方与管理员公钥，另建信任文件，例如：

```json
{"issuer": "<发行方 Ed25519 公钥的十六进制>", "registrar": "<管理员 Ed25519 公钥的十六进制>"}
```

```bash
.venv/bin/python audit_multiprocess_demo.py \
  --run-dir work/multiprocess/public_model_run \
  --trusted-anchors /path/to/independently-authenticated-anchors.json
```

复核脚本使用 Linux/POSIX 的 `O_NOFOLLOW`、目录文件描述符等能力防止沿符号链接读取；Windows 环境目前没有验证和适配，需另行实现等效的安全文件打开方式。

若仅为本机演示而把本次运行输出里的公钥复制到信任文件，审计只能说明在该本地信任假设下记录一致，不能证明公钥来自独立机构。进程结束后会话密钥已不可用，复核程序不会解密外层包，因而不能独立证明托管方保存的 ZIP 确实由该外层包解出；它也不验证指纹是否实际嵌入模型、本实验未留存的原始推理响应、外部模型来源、远程身份或登记是否为全局最新。缺失登记材料的旧运行不能直接套用该复核工具。

## 可信与安全边界

- 七个子进程分别持有角色密钥，但它们同属一个 OS 用户、一个文件系统，由同一个受信协调者控制；它们不代表五个独立机构、加密网络通道、硬件隔离或防恶意主机的安全边界。
- `RoleProcess` 使用本机 JSON 管道，管理员/分发者包含供内部使用的通用签名接口；路径与消息来自受信父进程。**不能把此 API 原样暴露到公网或交给不可信调用方。**
- 协调者生成并知晓会话秘密及所有份额，恢复时又看到参与者提交的份额值。分发者子进程也会收到会话秘密；这不是 DKG、不可导出密钥或门限解封。
- 签名记录和恢复回执使用本次运行内生成和传递的公钥；没有独立机构验证公钥真实性、可信时间、独立见证、持久防回滚/防分叉或持久防重放。当前回执只能作为本地服务的签名声明，无法阻止全部份额持有人离线恢复。
- 演示指纹参数和种子可预测，码本和探针在本地保存；签名与进程拆分不能防止攻击者复制或移除指纹，也不能仅凭命中认定真实泄漏人。
- 各角色的私钥、身份秘密和份额不持久保存；进程退出后，即使外层密文文件仍在，也无法仅凭它再次恢复模型。实际部署需要各方独立的密钥保管、备份、撤销和经认证的通信协议。
